# 관리자 화면 연결

연구진·공지사항·갤러리는 `/admin/`에서 편집합니다. 초대한 관리자 모두 미리보기 후 게시할 수 있습니다. 팝업·메인 슬라이드는 아직 JSON에서 관리합니다.

## 현재 상태

로컬 UI와 Netlify Functions 저장 코드를 준비했습니다. 실제 로그인·이메일 초대·운영 저장은 Netlify 설정 및 배포 후 검증해야 합니다. `npm run dev`로 실행한 로컬 관리자에서는 편집/미리보기만 가능하고 게시 버튼은 비활성화됩니다. 로컬 편집 내용은 저장되지 않습니다.

## 운영 설정 (사이트 소유자)

1. 이 변경을 PR로 검토한 뒤 배포합니다.
2. Netlify 프로젝트의 Identity를 Enable 합니다. Registration은 **Invite only**로 설정합니다.
3. Identity에서 관리자 이메일을 초대하고, 사용자에게 **admin** 역할을 부여합니다. 역할이 없는 계정은 콘텐츠 API에서 거부됩니다. 초대 이메일 발송은 사이트 소유자가 직접 진행합니다.
4. GitHub에서 이 저장소 하나만 대상으로 fine-grained access token을 발급합니다. Repository permissions는 **Contents: Read and write**만 필요합니다. 토큰은 브라우저 코드나 저장소에 넣지 않습니다.
5. Netlify 환경변수에 **CMS_GITHUB_TOKEN**을 추가합니다. Functions 범위, Production 컨텍스트에만 적용하고 재배포합니다. 토큰 만료일을 기록하고 만료 전에 교체합니다.
6. `/admin/`에서 초대 수락 → 비밀번호 설정 → 로그인 → 연구진/공지/갤러리 편집 → 미리보기 → 게시를 확인합니다. 초대/비밀번호 재설정 링크가 홈으로 도착하면 자동으로 `/admin/`으로 이동합니다.

저장은 지정된 GitHub 저장소의 main에 콘텐츠와 사진을 한 커밋으로 반영하며, 연결된 Netlify가 운영 배포합니다. 관리자는 GitHub 계정이 필요 없습니다. Git Gateway는 사용하지 않습니다. PR/브랜치 미리보기에서는 서버 저장을 거부합니다. main 보호 규칙이 직접 커밋을 막는 경우 저장도 실패하므로 배포 전 정책을 확인해야 합니다. 보호 규칙을 자동 변경하지 않습니다.

사진은 JPG/PNG/WebP, 최대 2MB입니다. 한 번에 한 장을 업로드하고 항목별로 게시합니다. 충돌이 나면 편집창 내용을 복사해 보관하고 목록 새로고침 후 변경사항을 비교하세요. 실패 시 성공으로 표시하지 않으며 서버 토큰을 로그나 응답에 노출하지 않습니다.

‘비공개’는 사이트 목록에서 숨기는 용도입니다. 저장소와 정적 JSON이 공개되어 있으므로 비밀 문서나 민감한 개인정보를 넣지 않습니다. 게시 완료 메시지는 GitHub 저장 성공이며, 실제 공개 사이트 반영은 Netlify 배포 성공 후입니다. 로그인·Functions·빌드는 사용 중인 Netlify 요금제의 사용량에 포함됩니다.

## 점검

- 비로그인 및 admin 역할 없는 계정이 읽기/게시 API를 이용할 수 없는지 확인
- 초대 수락, 비밀번호 재설정, 로그아웃 확인
- 실제 이미지와 공지를 게시하고 Netlify 배포 후 표시 확인
- 동시에 편집하면 덮어쓰지 않고 충돌 안내되는지 확인

공식 문서: https://docs.netlify.com/manage/security/secure-access-to-sites/identity/get-started/
